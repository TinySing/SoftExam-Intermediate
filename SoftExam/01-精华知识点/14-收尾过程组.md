# 第 14 章 收尾过程组

## 1. 结束项目或阶段

收尾是正式完成项目或阶段的过程，不是“最后一次会议”。它要确认成果完成、合同关闭、资料归档、知识沉淀、资源释放和责任移交。

### 收尾前提

- 可交付成果已经完成并通过质量检查。
- 客户或授权相关方依据验收标准正式接受。
- 所有变更、缺陷、问题和风险已处理或得到书面接受。
- 合同、采购、付款和索赔已处理。

### 收尾工作

1. 确认最终产品、服务或成果。
2. 取得正式验收或阶段批准。
3. 完成用户培训、运维交接和知识转移。
4. 关闭合同、采购和未结事项。
5. 归档计划、需求、设计、配置、测试、会议、合同和验收文件。
6. 收集和整理经验教训。
7. 编写最终报告，说明目标、绩效、偏差、风险和收益状态。
8. 释放团队、设备、场地和资金资源。

## 2. 系统集成项目验收

### 验收内容

- 项目范围和功能是否完成。
- 性能、可靠性、安全和兼容性是否达标。
- 设备、软件、接口和数据是否完整。
- 技术文档、用户手册、运维手册是否齐全。
- 培训、试运行、缺陷处理和移交是否完成。

### 验收流程

```text
准备验收材料 → 测试/试运行 → 提交验收申请
→ 相关方检查 → 记录问题 → 整改复验 → 正式签署
```

## 3. 项目移交

移交不只是把系统账号交给运维。应明确运行环境、资产、配置、权限、备份、监控、SLA、联系人、故障升级、培训和责任边界。

## 4. 项目总结

总结项目目标完成情况、范围/进度/成本/质量绩效、主要问题、风险应对、团队协作、采购履约、客户满意度和可复用经验。

经验教训应写成可行动内容：发生了什么、为什么发生、下次何时使用、由谁维护，而不是只写“以后加强管理”。

> [!warning] 易错
> 项目“开发完成”不等于项目“结束”。没有正式验收、归档、移交和资源释放，不能算完整收尾。

## 收尾自检

- [ ] 最终交付物已验收。
- [ ] 未关闭问题和风险有书面处置。
- [ ] 合同和采购已关闭。
- [ ] 配置、测试、验收和运维文档已归档。
- [ ] 经验教训和最终报告已完成。
- [ ] 人员、设备、资金和权限已释放或移交。

> 长内容直接按本章的“验收流程、项目移交、项目总结”三节复习。
