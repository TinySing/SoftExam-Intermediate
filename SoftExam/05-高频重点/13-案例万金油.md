# 案例万金油

> 本页根据 `new/案例万金油和万金油中油（助记标黄版）.pdf` 的“重要必记”和“重要必看”内容整理。标为“重要必记”的内容优先背诵，标为“重要必看”的内容重点理解答题方向。

## 1. 通用答题骨架

### 找问题

写成：**事实 + 违反的过程/原则 + 造成的影响**。

### 提措施

写成：**立即止损 → 补齐记录/文档 → 影响分析 → 评审审批 → 执行控制 → 跟踪验证 → 归档复盘**。

### 问原因

按直接原因、管理原因、制度/流程原因、技术或环境原因展开，不要把解决方案重复写成原因。

## 2. 立项与可行性

- 项目建议书：必要性、市场预测、预期成果市场预测和建设必需条件。
- 可行性研究：技术、经济、社会效益、运行环境、法律和组织实施。
- 详细可研：市场需求、部件和投入供应、系统架构与技术方案、技术设备、网络物理布局、投资成本资金、经济评价和综合分析。
- 常见问题：没有书面建议书就开工；技术论证不足；忽略人才、竞争和法律风险；缺少内部论证和外部评估。

## 3. 整合、范围与变更

- 项目章程写目的、目标、需求、范围、成果、风险、里程碑、财务资源、干系人、审批要求、退出标准、项目经理职权和批准人。
- 项目管理计划整合各子计划和范围、进度、成本基准。
- 变更流程：申请 → 记录 → 影响分析 → 评审 → 批准/拒绝 → 更新基准和文件 → 通知执行 → 验证关闭。
- 范围管理要有需求文件、范围说明书、WBS、WBS 词典、验收标准和需求跟踪矩阵。
- 不得把未经批准的新增功能直接纳入项目。

## 4. 进度与成本

- 进度问题：活动未基于 WBS、依赖关系遗漏、工期估算无依据、只排计划不监控。
- 缩短工期：快速跟进会增加返工和风险；赶工会增加资源和成本。
- 成本管理：明确估算依据，使用历史数据和专家判断，分解到工作包，建立成本基准，定期进行挣值分析。
- CPI<1 表示成本效率差、存在超支；SPI<1 表示进度落后。发现偏差要分析原因、预测完工并采取纠偏或变更。

## 5. 质量与资源

- 管理质量关注过程审计、质量改进和根因分析；控制质量关注成果检查、测试、测量和缺陷。
- 质量计划写标准、指标、测量方法、责任人、频率、检查和改进方式。
- 资源管理计划写角色职责、组织关系、资源获取、培训、团队建设、控制和释放。
- 团队冲突优先合作解决；使用培训、辅导、认可奖励、团队活动和沟通改善团队绩效。

## 6. 沟通、干系人和风险

- 沟通计划写对象、信息、时间、渠道、责任、反馈、升级和归档。
- 干系人管理：识别 → 分析权力/利益/影响/期望 → 制定参与策略 → 沟通协作 → 监督调整。
- 风险管理：识别 → 登记 → 定性/定量分析 → 责任人和应对 → 执行 → 监督触发条件、残余风险和次生风险。
- 威胁：规避、转移、减轻、接受；机会：开拓、分享、提高、接受。

## 7. 采购、合同、收尾和配置

- 采购前明确自制/外购、采购工作说明书、合同类型、供方标准和验收标准。
- 合同执行跟踪里程碑、交付物、付款、变更、索赔和违约。
- 验收依据合同和验收标准，完成测试、缺陷处理、文档确认、用户签字和书面记录。
- 收尾完成正式验收、运维交接、培训、合同关闭、资料归档、经验教训、资源释放和最终报告。
- 配置管理核心：识别、记录、控制、审计、发布；配置项包括需求、设计、代码、测试、计划、合同和交付物。

> [!important] 万能收尾句
> 应将问题记录到相应登记册，评估对范围、进度、成本、质量和风险的影响，提交正式变更请求，经授权审批后更新基准和计划；执行后验证结果并沉淀经验教训。

## 8. 招投标高频条款

- 招标人可以要求潜在投标人提供资质证明和业绩，但不得用不合理条件限制、排斥或歧视潜在投标人。
- 从招标文件发出到投标截止，给投标人编制文件的时间最短不得少于 20 日。
- 两个以上法人或组织可以组成联合体；同一专业组成的联合体，按资质等级较低的单位确定资质等级。
- 依法必须招标项目的评标委员会由招标人代表和技术、经济专家组成，成员 5 人以上且为单数，专家不得少于总数的三分之二。
- 中标通知书发出后 30 日内，招标人和中标人应按招投标文件订立书面合同，不得另订背离合同实质内容的协议。
- 国家安全、国家秘密、抢险救灾等特殊情况，按规定可以不进行招标。

## 10. 变更管理原文重点

### 常见变更原因

产品范围或项目范围定义疏漏、客户提出新需求、风险应急或规避、执行偏离基准、团队人员调整、技术革新、政策变化和自然环境变化。

### 变更分类

- 按性质：重大变更、重要变更、一般变更。
- 按迫切性：紧急变更、非紧急变更。
- 按行业特点：产品/工作范围变更、环境变更、设计变更、实施变更、技术标准变更。

### 教材版八步流程

1. 变更申请。
2. 对变更进行初审。
3. 变更方案论证。
4. 变更审查。
5. 发出通知并实施。
6. 实施监控。
7. 效果评估。
8. 变更收尾，判断项目是否重新纳入正常轨道。

助记：**申初论审，通监评收**。

变更不能只改代码或计划，还要同步更新相关技术文档、项目管理计划、基准、合同、版本和配置；最终结果要经过验证并得到客户或相关干系人确认。

## 11. 验收、总结与人员转移

### 四个验收阶段

1. 验收测试：编写测试用例、建立环境、全面执行、出具报告并签署。
2. 系统试运行：数据迁移、日常维护、缺陷跟踪修复和交接。
3. 系统文档验收：客户检查文档，所有文档验收合格并由双方签字。
4. 项目终验：试运行约定时间后进行最终验收，大型项目通常分试运行和终验两个步骤。

系统文件通常包括项目介绍、项目最终报告、信息系统说明手册、信息系统维护手册、软硬件产品说明书和质量保证书。

项目总结应由全体项目成员参加并共同形成文件，讨论项目绩效、技术绩效、成本绩效、进度绩效、沟通、问题解决以及意见建议；经确认后纳入组织过程资产和企业知识库。

人员转移前要确认转移条件已触发、任务和交付物已完成、工作已交接，项目经理完成转移确认和绩效文件，并通知相关干系人。

## 12. 配置管理重点

配置管理目标是系统地控制配置变更，在整个生命周期中保持配置的完整性和可跟踪性。

六项主要活动：制定配置管理计划、配置项识别、配置项控制、配置状态报告、配置审计、配置管理回顾与改进。助记：**计别控，报审改**。

### 配置项与状态

配置项包括项目计划、技术方案、需求、设计、源代码、可执行代码、测试用例、运行数据、设备型号和关键部件等。

状态有：草稿、正式发布、正在修改。配置项评审批准后成为正式发布；修改必须经过变更控制，修改完成并重新评审后再次正式发布。

### 配置库

- 开发库/动态库：开发人员当前工作区，自行控制。
- 受控库/主库：保存当前基线和基线变更，处于完整配置管理之下。
- 产品库/静态库：保存等待交付或现场安装的最终产品，访问严格受限。

助记：**开发—主—产品**。

配置审计用于防止错误版本交付、发现未按变更实施的内容、找出配置项不匹配、确认配置项经质量审核后进入基线，并保证记录和文档可追溯。

基于配置库的变更通常是：产品库取出基线 → 放入受控库 → 从受控库检出到开发库并锁定 → 修改后检入受控库并解除锁定 → 形成新基线并存入产品库，旧版本保留。
