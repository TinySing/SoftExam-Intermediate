# 输入、工具与输出（ITTO）汇总

## 先理解，不要机械背表

- **输入**：开始这个过程前需要的依据、计划、数据或文件。
- **工具与技术**：如何分析、组织、判断和执行。
- **输出**：这个过程产生或更新的成果、文件、数据和变更请求。

## 你要背什么

- [ ] 范围基准=范围说明书+WBS+WBS词典。
- [ ] 工作绩效数据=原始采集；工作绩效信息=与基准比较后的分析；工作绩效报告=面向决策者的汇总。
- [ ] 长清单按本页“项目文件主线”和“高频输出记忆”分组背，不要求一次背完整张表。

## 项目文件主线

| 文件 | 主要用途 |
| --- | --- |
| 项目章程 | 授权项目，记录目标、边界、高层需求和经理权限 |
| 项目管理计划 | 汇总各分项管理计划和基准，指导项目执行 |
| 范围说明书 | 明确项目范围、主要可交付成果和除外责任 |
| WBS/WBS 词典 | 把范围分解到可管理的工作包，并说明工作包内容 |
| 进度计划 | 记录活动、关系、持续时间、日期和里程碑 |
| 成本基准 | 经批准、按时间段分配的项目预算 |
| 风险登记册 | 记录风险、原因、概率、影响、责任人和应对 |
| 干系人登记册 | 记录干系人基本信息、影响、期望和参与策略 |
| 需求跟踪矩阵 | 把需求连接到来源、交付物、测试和验收 |
| 变更日志 | 记录变更请求的状态、评审结果和处理过程 |
| 问题日志 | 记录已发生的问题、责任人、期限和解决状态 |
| 经验教训登记册 | 在项目过程中持续记录可复用经验 |

## 基准与变更

范围基准 = **范围说明书 + WBS + WBS 词典**。

项目基准通常包括：

- 范围基准。
- 进度基准。
- 成本基准。

> [!important] 变更原则
> 基准一旦批准，不能直接改文件“覆盖过去”。应提交变更请求，评估影响，经授权的变更控制机构批准后更新基准、计划和相关文件。

## 高频输出记忆

| 过程类型 | 常见输出 |
| --- | --- |
| 规划类 | 管理计划、基准、估算、登记册、计划文件 |
| 执行类 | 可交付成果、工作绩效数据、问题日志、变更请求 |
| 监控类 | 工作绩效信息/报告、批准变更、验收成果、更新文件 |
| 收尾类 | 最终产品/服务/成果、最终报告、项目文件归档、经验教训 |

## 工作绩效三层

| 名称 | 发生阶段 | 回答的问题 |
| --- | --- | --- |
| 工作绩效数据 | 执行中直接采集 | 实际发生了什么 |
| 工作绩效信息 | 监控中与基准比较 | 为什么有偏差 |
| 工作绩效报告 | 汇总后对外沟通 | 现在状态如何、需要什么决策 |

> [!warning] 易错
> “报告”不是原始数据；需要分析、比较和汇总后才形成信息或报告。
