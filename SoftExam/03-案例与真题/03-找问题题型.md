# 找问题题型总结

## 必须背的短句

- [ ] 所有问题答法：事实→违反的过程/原则→影响→整改动作→验证关闭。
- [ ] “加强沟通”要写成：对象+频率+渠道+责任人+反馈记录+升级路径。
- [ ] 变更答法：记录→影响分析→授权审批→更新基准→执行测试→验证关闭。
- [ ] 长清单就在本页“高频问题清单”，按范围、进度、成本、质量、资源、沟通、风险、采购、配置、收尾分组背。

## 找问题的四步法

1. **找事实**：谁在什么时候做了什么，缺了什么文档、审批或验证。
2. **找依据**：对应哪个过程、计划、基准、合同条款或安全要求。
3. **找后果**：会造成范围蔓延、返工、延期、超支、质量缺陷、风险扩大或验收失败。
4. **写措施**：补文档、走流程、指定责任、设置检查点、跟踪关闭。

## 高频问题清单

### 立项与章程

- 未做可行性研究就直接实施。
- 项目目标不可测量，范围和验收标准不清。
- 项目经理未获得正式授权，职责和权限不匹配。

### 需求与范围

- 需求靠口头传递，没有记录、确认和跟踪。
- 需求变更直接开发，没有影响分析和审批。
- WBS 漏项、重复、分解过粗或把组织结构当作 WBS。
- 把不属于项目范围的工作随意加入。

### 进度

- 活动没有来自 WBS，依赖关系和外部依赖未识别。
- 估算没有依据，关键路径和里程碑没有识别。
- 进度偏差后只要求加班，没有分析根因和评估风险。
- 直接并行或赶工，没有比较成本、质量和返工风险。

### 成本

- 没有统一估算口径，成本未分解到工作包。
- 未建立成本基准，实际花费无人跟踪。
- 用“花了多少钱”代替挣值分析。
- 超支后私自增加预算，未走变更流程。

### 质量

- 质量标准模糊，没有指标、测量方法和责任人。
- 只在最后测试，缺少评审、审计和过程质量控制。
- 缺陷没有登记、分派、修复、回归验证和关闭。
- 重复缺陷只修产品，不改过程和根因。

### 资源与团队

- 资源未按计划获取，设备、环境和人员能力不足未提前识别。
- 角色职责不清，出现多人负责或无人负责。
- 团队冲突被回避，重要问题没有升级和决策记录。
- 人员离职没有交接、备份和知识沉淀。

### 沟通与干系人

- 信息只发送不确认，受众、频率和渠道不匹配。
- 重要会议无议程、无纪要、无责任人和截止时间。
- 关键干系人未识别或只在出问题后沟通。
- 客户意见没有进入需求、问题或变更记录。

### 风险

- 把已发生的风险仍放在风险登记册，不转为问题。
- 只识别技术风险，忽略人员、供应商、法律、进度和安全风险。
- 没有责任人、触发条件、应急措施和残余风险。
- 风险应对计划写了但没有执行和跟踪。

### 采购与合同

- 采购范围、技术要求、验收标准和付款条件不清。
- 只看价格，不评估质量、交付和供方能力。
- 供方交付偏差未按合同处理，缺少绩效审查和索赔记录。
- 合同变更没有书面确认，导致责任和费用争议。

### 配置与变更

- 配置项没有唯一标识、版本和状态。
- 基线未经评审或被直接覆盖。
- 变更没有记录、影响分析、审批和回退方案。
- 发布前没有配置审计、测试和备份。

### 验收与收尾

- 交付物未按验收标准确认就交付运行。
- 文档、培训、运维和知识转移不完整。
- 未关闭采购和合同，未归档项目资料。
- 项目总结只写成绩，不记录问题、原因和经验教训。

## 措施不要写空话

| 空话 | 改成可得分的表述 |
| --- | --- |
| 加强沟通 | 制定沟通计划，明确对象、频率、渠道、责任人和反馈确认方式 |
| 提高质量 | 设置评审、测试、质量指标和缺陷闭环，定期开展质量审计 |
| 加强风险管理 | 更新风险登记册，指定责任人、触发条件、应对措施和跟踪频率 |
| 控制变更 | 提交变更请求，评估范围/进度/成本/质量/风险影响，经授权审批后执行 |
| 加强团队建设 | 做能力评估、培训、辅导、认可奖励和冲突解决，并跟踪效果 |

> [!question] 自测
> 看到“客户临时增加功能、开发已开始、计划未更新”，至少能写出：需求记录、影响分析、变更审批、更新基准、通知执行、验收验证六个得分点。
